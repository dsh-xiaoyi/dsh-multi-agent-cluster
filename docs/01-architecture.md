# 三中枢架构

> 第一次读到这里，不必一次记住；先照着跑一遍，遇到问题再回来查对应那一节。
## 一句话

三中枢是**一个智能体的"大脑与左右手"**，不是三个可以互相替代的独立服务。

```
              智能体（DSH）
                      │
    ┌─────────────────┼──────────────────┐
  【大脑】          【右手】            【左手】
  记忆中枢         青鸟交互中枢        时光守护中枢
```

| 部位 | 中枢 | 类比 | 承担 |
|---|---|---|---|
| 大脑 / 神经网络 | 记忆中枢 | 记忆与联想 | 记住、检索、注入、备份、恢复 |
| 右手（主力手） | 青鸟交互中枢 | 伸出去递东西 | 通信、文件传输、任务分发 |
| 左手（持盾） | 时光守护中枢 | 挡在身前 | 规则判定、发现、心跳、紧急修复 |

## 三条职责边界（防退化）

```
① 记忆中枢只"记、查、恢"，不做实时投递（投递是青鸟的事）
② 时光守护中枢只"发现与判定"，不替人做决定（尤其"删数据"：只提醒，决定权在用户）
③ 青鸟交互中枢只"搬运"，不做判定（搬运丢了能补；判定丢了就没人知道出事了）
```

## 与"可靠通道"的关系

三中枢都是**能力归属**，不是单点替代：

```
青鸟可以挂，队列不能丢；记忆中枢可以慢，审计链不能断。
任何"把某中枢当唯一通道"的设计，都要先回答：它挂了，谁补位？
```

## 落点可以变，命名不变

- 单机：三中枢都在同一台机器（本项目默认形态）
- 多机：记忆中枢在库主机；青鸟、时光守护按机器分布
- **判断某功能属于哪个中枢，看它在替智能体做哪件事，不看它跑在哪台机器**
