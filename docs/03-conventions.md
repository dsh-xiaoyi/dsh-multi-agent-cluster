# 运维纪律（判据与通道）

> 第一次读到这里，不必一次记住；先照着跑一遍，遇到问题再回来查对应那一节。
## 一、判据纪律

```
一义    ：只判"出现了什么"（如出现了 inject failed），不判"缺少什么"
          （"没消息"= 空闲 还是 故障？无法区分，就不能当判据）
有分母  ：误报率必须给"抽样 N 中 M"；0/0 就写"不可测"，不写 0%
不抖动  ：判据要扣掉不可避免的实时尾/采样相位
相位量  ：ACK 与信封的时间差这类"相位相关量"，不得写成阈值或区间
只发现  ：端口每次启动都会变 → 只发现不持久化（port 文件 + /healthz）
不等于  ："插件已加载" ≠ "能注入"；"清单说有" ≠ "机器上有"
```

## 二、通道职责

```
队列（dbo.agent_messages）= 可靠通道：任务/结果/回执/审计走它（可重试、可离线补）
青鸟（HTTP，实时）       = 实时通道：只发"现在就要"的短指令，发出后仍落一条库记录

聊天注入要求目标会话活跃；空闲 ⇒ 502 / inactive context ⇒ 聊天不能当送达保证
delivered_at 是"终态"，不是"成功"：
   成功 = delivered_at 非空 且 last_error 为空
   失败 = delivered_at 非空 且 last_error 非空
   在途 = delivered_at 为空

一句话：中枢可以丢，队列不能丢。
```

## 三、重启与身份

```
改插件（index.mjs / cordis.patch.yml）⇒ 必须紧跟一次 DSH 重启，否则后续注入全失败
重启"用户可见的 GUI"必须用登录用户身份；
SYSTEM 任务起的是 session 0（看不见）——曾经因此产生"幽灵实例"
```

## 四、权限

```
DDL 只在库主机上用 sysadmin 执行；应用账号只读写（这是设计，不是缺陷）
恢复类演练必须 sysadmin；平时脚本用应用账号
任何"删数据"的动作：默认不删，只提醒，决定权在用户
```

## 五、部署与变更

```
契约在库（表：manifest），字节可取（表：file_transfer），镜像可选（共享盘）
清单必须带"行数下限"断言，否则被截断的清单会静默通过
哈希校验：本地文件 ↔ 契约 ↔ 镜像，三处一致才算"部署成功"
```

## 六、发布前脱敏（经验条款）

```
① 脱敏**只能作用于"已渲染的示例值"**（即示例配置文件里的值），
   请不要对"代码里的字符串拼接"做正则替换 ——
   我们曾经这样做过，结果：把 `";Password=" + $cfg.password` 替换成 `;Password=EXAMPLE_PASSWORD`，
   引号被吞掉，脚本直接语法错误，而且本地没人跑过就差点发出去。

② 脱敏后必须做三件事，缺一不可：
   · 所有 .ps1 过一遍 Parser 检查；所有 .mjs 过一遍 node --check
   · ops\secret-scan.ps1 全仓扫描，BLOCK 必须为 0
   · 用一个"陌生人视角"读一遍 README：按里面的命令能不能真的跑起来

③ 公开仓库里不要出现：真实 IP / 主机名 / 账号 / 口令 / 令牌 / 私钥 / 个人对话数据。
```
